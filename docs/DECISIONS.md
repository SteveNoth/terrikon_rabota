## 2026-08-28 — Выбор стека

**Решение:** используем полностью бесплатный стек на старте.

**Обоснование:** раздел 5 ядра (`ПРОМТ_1_ЯДРО.md`) — Next.js + Supabase + Vercel + GitHub Actions. Каждый внешний сервис спрятан за адаптером, чтобы потом можно было заменить без переписывания всего проекта.

**Кто принял:** автор проекта + ИИ-напарник на Этапе 0.

## 2026-08-29 — Prisma 6, не 7

**Решение:** фиксируем Prisma ORM **6.19.x** и генератор `prisma-client-js`.

**Обоснование:** в ядре URL лежит в `schema.prisma` (`DATABASE_URL` + `DIRECT_URL`), клиент импортируется из `@prisma/client`. Prisma 7 убирает URL из схемы, требует `prisma.config.ts` как единственный источник и драйвер `@prisma/adapter-pg`. Это другой шов и лишние пакеты — на Этапе 4 не нужно.

**Как живём с 6.19:** файл `prisma.config.ts` всё же есть — его начал генерировать сам `prisma init`. Он нужен CLI для миграций (берёт `DIRECT_URL`) и сидов. Рантайм сайта по-прежнему читает `DATABASE_URL` из схемы.

**Альтернативы, которые отклонили:** Prisma 7 «потому что latest».

**Кто принял:** ИИ-напарник на Этапе 4 (чтобы схема из ядра совпала с реальностью).

## 2026-08-29 — Серверные функции Vercel в Франкфурте (`fra1`)

**Решение:** сайт и API крутятся в регионе `fra1`, рядом с базой Supabase (`eu-central-1`). Записано в `vercel.json`.

**Обоснование:** бюджет ответа `/api/vacancies` — 400 мс. Если функция живёт в США (регион Vercel по умолчанию), один только путь до базы в Франкфурте съедает этот бюджет.

**Альтернативы, которые отклонили:** оставить регион по умолчанию.

**Кто принял:** ИИ-напарник на Этапе 5.
