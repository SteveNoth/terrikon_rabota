## 2026-08-29 — Prisma 6, не 7

**Решение:** фиксируем Prisma ORM **6.19.x** и генератор `prisma-client-js`.

**Обоснование:** в ядре URL лежит в `schema.prisma` (`DATABASE_URL` + `DIRECT_URL`), клиент импортируется из `@prisma/client`. Prisma 7 убирает URL из схемы, требует `prisma.config.ts` как единственный источник и драйвер `@prisma/adapter-pg`. Это другой шов и лишние пакеты — на Этапе 4 не нужно.

**Как живём с 6.19:** файл `prisma.config.ts` всё же есть — его начал генерировать сам `prisma init`. Он нужен CLI для миграций (берёт `DIRECT_URL`) и сидов. Рантайм сайта по-прежнему читает `DATABASE_URL` из схемы.

**Альтернативы, которые отклонили:** Prisma 7 «потому что latest».

**Кто принял:** ИИ-напарник на Этапе 4 (чтобы схема из ядра совпала с реальностью).

## 2026-08-29 — Ultra Lite: отдельный тонкий путь `/u/...`

**Решение:** режим `ultra` обслуживается отдельным тонким путём. Middleware незаметно переписывает запрос на `/u/...`, обработчик собирает HTML строкой. React и его рантайм в браузер не едут. Адрес в строке браузера не меняется.

**Обоснование:** раздел 8.6 ядра и бюджеты 8.5. На Этапе 9 даже Ultra тянул ~192 КБ JavaScript — каркас Next.js. На 50 Кбит/с это ~31 с скачивания, плюс preload скриптов отбирает канал у текста. Группа маршрутов без клиентских компонентов дала бы ~90 КБ JS и заставила бы поднять бюджет Ultra до ~130 КБ — это ломает обещание «0 КБ JavaScript» и «≤ 40 КБ».

**Компромисс:** разметку главных экранов описываем вторым, простым способом. Данные — те же `src/lib/repo`, вид карточки — тот же `VacancyView` (Закон 15), цвета — те же токены из `src/styles/tokens.css`.

**Альтернативы, которые отклонили:** группа маршрутов App Router без `"use client"` (JS не ноль, бюджет не закрывается).

**Кто принял:** автор проекта на Этапе 10.

## 2026-08-29 — Offline: версия кэша и сеть важнее коробки

**Решение:** service worker кладёт в кэш только ответы со статусом 200. Оболочка (хешированные `/_next/static`, иконки, шрифты) — сначала кэш, обновление в фоне. HTML и `/api/vacancies` — сначала сеть, кэш только если сеть не ответила. Имена кэшей содержат `CACHE_VERSION`; при activate старые коробки удаляются. Новая версия SW не включается сама: нужна кнопка «Обновить приложение». Регистрация только в production.

**Обоснование:** раздел 8.7. Service worker страшен тем, что может навсегда показать ошибку или вчерашнюю страницу. Не кэшируем 4xx/5xx, админку, `/login`, API парсера, события, жалобы, очередь офлайна и `/api/ping` (иначе замер качества врёт). HTML не cache-first: после деплоя закэшированная страница указывала бы на старые хеши `/_next/static`. Ultra не регистрирует SW (0 КБ JS); офлайн там работает, если SW уже поставили из Full/Lite.

**Альтернативы, которые отклонили:** cache-first для всего HTML «как в учебнике PWA»; регистрация SW в `next dev` (ломает отладку).

**Кто принял:** ИИ-напарник на Этапе 11.

Список доменов расширяем, когда появится реальный источник, а не «на всякий случай».

**Альтернативы, которые отклонили:** грузить любой https через `<img unoptimized>` в Full; прокси `/api/logo`.

## 2026-08-30 — Карта: MapLibre из public/, не из бандла Next

**Решение:** библиотека MapLibre GL 6 не импортируется в граф Next. Скрипт `scripts/copy-maplibre-worker.mjs` копирует `maplibre-gl.mjs`, воркер, shared и CSS в `public/maplibre/`. Страница карты подключает их только после клика «Показать карту» (Full) или «Открыть интерактивную карту» (Lite).

**Обоснование:** Этап 13 и Закон 4. `next build` (Turbopack) не умеет собрать воркер MapLibre 6 (`new URL(..., import.meta.url)` → `Can't resolve <dynamic>`). Даже `setWorkerUrl` не спасает: ошибка на этапе сборки, не в рантайме. Вынести ESM на тот же сайт — единственный способ и собрать проект, и не тащить ~500 КБ карты в первую загрузку главной.

**Как живём:** `npm run dev` / `npm run build` / `postinstall` копируют файлы. Папка `public/maplibre/` в gitignore. Провайдер по-прежнему `MAPS_PROVIDER` (maplibre | yandex | static | none); компоненты спрашивают адаптер, не имя сервиса. «Открыть в навигаторе» — https (OSM или Яндекс), не `geo:`: на Windows в браузере `geo:` ничего не открывает.

**Альтернативы, которые отклонили:** даунгрейд MapLibre 4 (устаревший API); `next build --webpack` только ради одной библиотеки; CDN unpkg (лишний хост и CSP).

**Кто принял:** ИИ-напарник на Этапе 13.

## 2026-08-30 — Геокодер только из парсера и админки, с кэшем навсегда

**Решение:** страница карты читает уже сохранённые `latitude` / `longitude` / `geocodeAccuracy`. Внешний запрос — `maps.geocode()` через Nominatim (или Яндекс, если есть ключ) с паузой 1.1 с и честным User-Agent. Обёртка `resolveVacancyCoordinates` / `applyVacancyGeocode`: город не `active` → сети нет; тот же адрес → строка `GeocodeCache`; не распознали → центр района, иначе города, точность `exact` / `district` / `city`.

**Обоснование:** правила Nominatim (лимит 1 запрос/с, обязательный User-Agent) и Закон 10. Сиды не ходят в Nominatim — пишут кэш сами.

**Альтернативы, которые отклонили:** геокодировать при отрисовке страницы; кэшировать ошибку сети (тогда адрес никогда не переспросим).

**Кто принял:** ИИ-напарник на Этапе 13.

## 2026-08-30 — Дверь парсеров: секрет в заголовке, не в адресе; без автопубликации

**Решение:** `POST /api/parser/upload` пускает только `Authorization: Bearer <CRON_SECRET>` (≥ 32 символа). Секрет не кладём в путь URL. Пачка до 100 записей. `PENDING` не попадает ни на страницы, ни в публичные API. Автопубликации «если не проверил за N часов» нет и не будет. Нечёткая группировка — ночным `scripts/regroup.py` в GitHub Actions, не в этом запросе.

**Обоснование:** Закон 18 и раздел 11.5 / 11.17. Секретный путь `/api/parser/upload-a8f3...` светится в логах прокси, истории браузера и реферерах. Bearer можно сменить, не меняя адреса. Пачка — один RTT и одна строка `ParserRun`. 10 секунд Vercel не тянут шинглы по всей базе.

**Альтернативы, которые отклонили:** секрет в query `?key=`; по одной вакансии на запрос; отложенная публикация PENDING.

**Кто принял:** ИИ-напарник на Этапе 15.

## 2026-08-30 — Сайты предприятий: HTML по robots.txt, Playwright только если нужно

**Решение:** парсер читает публичные страницы вакансий предприятий (`requests` + BeautifulSoup). Playwright и браузер Chromium включаем, только если страница без JavaScript пустая и в `config_web.json` стоит `javascript: true`. `robots.txt` проверяем до обхода, запрещённые пути не открываем. Выключатель `SOURCE_WEB_ENABLED`. Карточку парсер не собирает — только `process_post`. Источник в базе: `WEBSITE`.

**Обоснование:** Закон 12, 15 и 19, класс `COMPANY_SITE`. Установка Chromium в Actions на каждый запуск съедает 1–3 минуты и ~150 МБ; оба первых источника отдают вакансии в HTML. Тихий ноль при смене вёрстки скрыл бы смерть парсера.

**Альтернативы, которые отклонили:** всегда ставить Playwright «на всякий случай»; парсить hh.ru по ссылке с карьеры ЮГМК; игнорировать `robots.txt`.

**Кто принял:** ИИ-напарник на Этапе 18.

## 2026-08-31 — Этап 20A: кабинетный контур политики и отдельная очередь

**Решение:** между кабинетом работодателя (20) и кабинетом соискателя (21) вставляем Этап 20A. Нумерацию 21–32 не сдвигаем. Стопроцентный запрет (жёсткий флаг, СВО, чёрный список) — отказ сразу с фразой в кабинете. **Альтернативы, которые отклонили:** прогон формы через `process_post`; второй словарь «для кабинета»; публикация только после `isVerified`; все кабинетные вакансии вечно вручную; одна общая `/admin/queue`; бан только в Supabase.

## 2026-08-31 — Этап 21: избранное без регистрации, отклик только с замком APPLY

**Решение:** избранное живёт в IndexedDB без входа и после входа переносится в `Favorite`. Отклик всегда идёт через форму `/profile/apply/[id]`: сначала `assertCanApply`, потом одна строка `Application`. Повторный отклик не создаётся (`@@unique`). Без сети очередь Этапа 11 досылает отклик один раз; без сессии очередь не помечает его отправленным. В списках откликов и избранного — только вакансии городов `active`. Код привязки Telegram выдаём в профиле, webhook бота не пишем.

**Обоснование:** смотреть вакансии без регистрации — закон проекта. Заставлять регистрироваться ради звёздочки — потерять человека на слабой сети. Отклик без замка APPLY (20A) открыл бы спам в тот же день. Города `soon`/`planned` не должны ломать кабинет при переключении селектора.

**Альтернативы, которые отклонили:** избранное только после входа; отклик кнопкой без формы; отдельная очередь без `assertCanApply`; писать бота на этом этапе.

**Кто принял:** ИИ-напарник на Этапе 21.

## 2026-09-02 — Этап 22: бот через webhook, рассылка отдельно от двери парсера

**Решение:** Telegram Bot API, webhook `POST /api/telegram/webhook` с заголовком `X-Telegram-Bot-Api-Secret-Token`. Подписка живёт в `TelegramUser` (город из `active`, слова, сферы). Привязка к кабинету — `/link КОД` или `t.me/<бот>?start=<код>` пишет `TelegramUser.userId`. Рассылка — `POST /api/telegram/notify` по `CRON_SECRET`, не внутри `/api/parser/upload`. Одна вакансия (группа дублей) — одна доставка: таблица `TelegramDelivery`. Не чаще 8 сообщений в час на человека. Пауза 40 мс между сообщениями. Шаг GitHub Actions сразу после каждого парсера.

**Обоснование:** дверь парсера уже упирается в 10 секунд Vercel. Telegram ждёт короткий ответ на webhook. Закон 3: названия городов только из geo.json. Закон 6: страницы зовут `notify.send`, бот — `src/lib/telegram/api.ts`. Кнопки на телефоне важнее «голой» команды.

**Альтернативы, которые отклонили:** слать из `/api/parser/upload`; long polling; Telethon для бота (это парсер каналов, Этап 17); хранить «уже послали» только в `lastNotifiedAt` без журнала доставки.

**Кто принял:** ИИ-напарник на Этапе 22.

## 2026-09-02 — Этап 23: канон без фильтров, sphere — посадочная; чужое не своё

**Решение:** канонический адрес страницы списка — путь без `page`, `sort`, `mode`, `q` и прочих фильтров. Параметр `sphere` оставляем: это отдельная посадочная («Работа в строительстве в Горловке»), она же попадает в sitemap. `JobPosting.hiringOrganization` — работодатель или «Работодатель не указан», никогда «Террикон Работа». Сайт в разметке — `publisher`. Источник — в описании и в `sameAs`/`isBasedOn`, если есть URL оригинала. Sitemap один файл, пока URL ≤ 5000; иначе индекс и `/sitemaps/0`, `/sitemaps/1`. Публичная страница компании — `/{city}/company/{slug}`, кабинет `/employer` закрыт от индекса. Превью для мессенджеров рисуется из текста (`opengraph-image`), цвета из `tokens.css`. Заголовок и канон главной города живут в `[city]/page.tsx`, не в layout: иначе Next склеивает мета главной со списком и карточкой. Тонкий путь Ultra не переписывает `/opengraph-image`, `/robots.txt` и `/sitemap.xml` — это картинка и файлы для роботов, не HTML.

**Обоснование:** этап 23. Закон 3 — падежи из geo.json. Закон 5 — предложный падеж сферы в `professions.json`. Закон 12 — не выдаём чужие объявления за свои. Закон 15 — в JSON-LD реконструкция полей, не сырой HTML источника.

**Альтернативы, которые отклонили:** канон на `?page=2`; employer-страницы внутри `/employer`; тяжёлая картинка 1200×630 с отдельной палитрой.

**Кто принял:** ИИ-напарник на Этапе 23.

## 2026-09-02 — Этап 24: честный health, долг Lite JS, пауза Supabase

**Решение:** `/api/health` публичный: 200 если сайт может работать (в том числе с «просевшими» парсерами), 503 только если база молчит или миграции не накатаны. Парсеры ВК/Telegram считаем затихшими через 6 часов, сайты предприятий и ЦЗН — через 26 часов: они сами ходят раз в сутки, 6 часов дали бы ложную тревогу каждую ночь. Замеры LCP/CLS/INP пишет браузер в Full/Lite; Ultra — только факт захода с сервера (0 КБ JS, Закон 4). `check:budget` валит сборку, если клиентский JS > 220 КБ gzip (потолок Full 8.5) или в `src` появляется `moment`/`lodash`/`recharts`/`maplibre-gl` как импорт Next. Потолок Lite 90 КБ каркас Next.js по-прежнему не закрывает — это долг, не красный провал.

**Обоснование:** этап 24. Закон 14 — в `RumSample` нет сессии, IP и строки браузера. Бесплатный Supabase засыпает примерно через неделю без запросов к базе; GitHub Actions раз в 3 дня дергает health.

**Альтернативы, которые отклонили:** 503 на любой «жёлтый» парсер (тогда keep-alive казался бы аварией); библиотека web-vitals; падать на Lite JS 90 КБ при уже известном каркасе ~200 КБ.

**Кто принял:** ИИ-напарник на Этапе 24.
