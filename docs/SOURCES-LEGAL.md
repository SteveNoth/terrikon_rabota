# Источники данных — что разрешено

Закон 19: правила источника сильнее наших планов. Отказ сервера (`403`, требование ключа) — это «нельзя», а не задача на обход. Здесь фиксируем проверку **до** написания парсера: что именно читаем, чем это подтверждено, дату и что **решили не делать**.

Выключатель каждого источника — переменная в `.env` / GitHub Secrets. Правила меняются: отключение должно занимать минуту, не переписывание кода.

## ВКонтакте (класс `SOCIAL`) — Этап 16

| Поле | Значение |
|---|---|
| Дата проверки | 2026-08-30 |
| Класс | `SOCIAL` (публичные посты; карточку собираем заново, Закон 15) |
| Что читаем | Последние посты **открытых** стен сообществ методом `wall.get` |
| Чем подтверждено | Официальная документация VK API: метод `wall.get` (https://dev.vk.com/method/wall.get), токен и версия API (https://dev.vk.com/api/access-token/getting-started, https://dev.vk.com/reference/versions). Создание приложения: https://vk.com/apps?act=manage и https://vk.com/editapp?act=create |
| Выключатель | `SOURCE_VK_ENABLED` (`true` / `false`). Токен — `VK_TOKEN`, не в git |
| Код | `scripts/parser_vk.py`, список групп `scripts/sources_vk.json` |

### Что такое `access_token` и `v`

- **`access_token`** (токен доступа) — это пароль приложения к API на время. Его выдаёт ВКонтакте после того, как ты создал приложение и разрешил ему читать открытые данные. Без токена метод `wall.get` не отвечает. Токен **нельзя** класть в репозиторий, в `sources_vk.json` и в логи: кто его украдёт, тот ходит в API от нашего имени.
- **`v`** — версия API, обязательный параметр каждого запроса. Методы меняют формат ответа; номер версии фиксирует контракт. Сейчас в коде стоит `5.199` (переменная `VK_API_VERSION`, если нужно сменить без правки кода). Запрос без `v` API отклоняет.

### Что мы делаем

- Только официальный HTTPS-запрос к `https://api.vk.com/method/wall.get` (и при необходимости `groups.getById`, чтобы из короткого имени группы узнать `owner_id`).
- Текст и картинки — из JSON ответа. Картинки **не** скачиваем в git и **не** кладём в базу: в `process_post` уходят URL с хостов из `shared/ocr.json` → `downloadAllowHosts`.
- Пауза между запросами (по умолчанию 1.5 с), уважение лимита API. Ошибка «слишком часто» — ждём и повторяем, а не долбим.
- У каждой вакансии ссылка на оригинал вида `https://vk.com/wall-123_456` и человекочитаемое `sourceName` из конфига группы.

### Что мы решили не делать

- Не открывать `vk.com/club…` как HTML-страницу и не вырезать посты из вёрстки.
- Не подменять `User-Agent` под браузер и не крутить прокси, чтобы «притвориться человеком».
- Не брать чужие токены, не логиниться паролем пользователя из скрипта, не обходить капчу.
- Не читать закрытые стены, посты «только для подписчиков» и контент за донат (`donut`), если API его не отдаёт открыто.
- Если API отвечает «нельзя» (`15`, `203`, `403`) — группу выключаем в `sources_vk.json` (`enabled: false`) или весь источник — `SOURCE_VK_ENABLED=false`. Не «пробиваем».

Почему обход интерфейса недопустим: это прямое нарушение Закона 12 и 19 и правил ВКонтакте. Сайт живёт на чужих данных; одно письмо от площадки закрывает и агрегатор, и статистику. Официальный API с токеном — штатный путь для чтения открытых стен. HTML вместо API — чтение в обход, даже если «технически получилось».

## Telegram (класс `SOCIAL`) — Этап 17

| Поле | Значение |
|---|---|
| Дата проверки | 2026-08-30 |
| Класс | `SOCIAL` (публичные посты; карточку собираем заново, Закон 15) |
| Что читаем | Последние сообщения **публичных** каналов через клиентский API Telegram (MTProto) |
| Чем подтверждено | Официальные инструменты разработчика: https://core.telegram.org/api и создание приложения на https://my.telegram.org (раздел API development tools: `api_id` + `api_hash`). Библиотека Telethon реализует тот же протокол, что официальные клиенты, а не разбор HTML `t.me`. Условия: https://telegram.org/tos, https://core.telegram.org/api/obtaining_api_id |
| Выключатель | `SOURCE_TG_ENABLED` (`true` / `false`). Секреты — `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` (строка StringSession), не в git |
| Код | `scripts/parser_tg.py`, список каналов `scripts/sources_tg.json`, сессия `scripts/make_tg_session.py` |

### Что такое `api_id`, `api_hash` и строка сессии

- **`api_id` и `api_hash`** — номер и ключ приложения, которое ты регистрируешь на https://my.telegram.org. Без них клиентский API не принимает соединения. Это не токен бота из `@BotFather` (тот нужен Этапу 22) и не пароль аккаунта.
- **Строка сессии (`StringSession`)** — упакованный вход в аккаунт. После того как один раз ввёл телефон и код из Telegram, библиотека больше не спрашивает SMS: она предъявляет эту строку. По смыслу это **тот же ключ, что файл `*.session`**: кто её украдёт, читает каналы и личку от твоего имени и может писать сообщения.
- Файл `*.session` — база SQLite на диске. Его нельзя класть в git: репозиторий копируют, форкают, логи Actions его напечатают. Строку создаём **один раз локально** (`python scripts/make_tg_session.py`) и кладём в `.env.local` и GitHub Secrets. В Actions нет телефона и SMS — только готовая строка.

### Что мы делаем

- Только MTProto-клиент с нашими `api_id` / `api_hash` и своей сессией. Читаем публичные каналы из `scripts/sources_tg.json`.
- Альбом (несколько сообщений с одним `grouped_id`) склеиваем в один пост **до** `process_post`. Это куски одного объявления, не нарезка 14A.
- Картинки не кладём в git и не в базу: в `process_post` уходят URL на хостах из `shared/ocr.json` → `downloadAllowHosts`; байты, если OCR включён, скачивает тот же клиент.
- Пауза между каналами. Ошибка «слишком часто» (`FloodWait`) — ждём указанное число секунд и продолжаем, а не падаем.
- У каждой вакансии ссылка на оригинал вида `https://t.me/channel/123` и человекочитаемое `sourceName` из конфига канала.

### Что мы решили не делать

- Не открывать `t.me/s/channel` как HTML-страницу и не вырезать посты из вёрстки.
- Не подменять `User-Agent` под браузер и не крутить прокси, чтобы «притвориться человеком».
- Не брать чужие сессии, не логиниться паролем из скрипта парсера (телефон и код — только в одноразовом `make_tg_session.py` на твоей машине).
- Не читать закрытые каналы, чаты «только для подписчиков» и комментарии, если API отвечает «нельзя».
- Не класть `*.session` и строку `TG_SESSION` в репозиторий, в `sources_tg.json` и в логи.
- Если Telegram отвечает, что канал частный или имя не существует — канал выключаем в `sources_tg.json` (`enabled: false`) или весь источник — `SOURCE_TG_ENABLED=false`. Не «пробиваем».

Почему обход интерфейса недопустим: Закон 12 и 19. HTML вместо client API — чтение в обход, даже если «технически получилось». Client API с приложением с my.telegram.org — штатный путь, тем же протоколом пользуются официальные клиенты. Бот из `@BotFather` видит только каналы, куда его добавили; нам нужен обход публичных каналов по списку, поэтому здесь Telethon, а не Bot API.

| Что читаем | HTML страниц из `scripts/config_web.json`, только если `robots.txt` не запрещает путь |

| Код | `scripts/parser_web.py`, список `scripts/config_web.json` |

Проверено 2026-08-30:

- **ГУП ДНР «Вода Донбасса»** `https://vodadonbassa.ru/job-openings/` — `robots.txt` отвечает 404 (нет запретов). Вакансии в HTML (аккордеон филиалов), JavaScript для раскрытия не нужен. Берём только блок «Горловское ПУВКХ».
- **ГУП ДНР «Донбасстеплоэнерго»** `https://dtedn.ru/o-predpriyatii/vakansii2?department[]=4` — `robots.txt` запрещает `/manager/`, `/connectors`, `/core`, `/?`. Путь вакансий с фильтром Горловкатеплосеть не запрещён. Карточки `.card-job` в HTML.
- **ЮГМК** `https://ygmk.ru/vacancies/` — список вакансий ведёт на `hh.ru`. HTML hh.ru не читаем. Сайт в конфиг не добавляли.
- **Горловская мозаика** `https://mozaika.biz/vakansy/` — `robots.txt` явно разрешает `/vakansy/` и запрещает `*/page/` и `/*?*`. Берём только первую страницу списка. Часто те же объявления, что группа ВК `rabota.gorlovka`: дубли схлопнет приём (сигнатура / шинглы), источник всё равно указываем.
- **Работа ДНР** `https://rabotadnr.com/job/vacancy/city/gorlovka` — `robots.txt` отвечает 404 (запретов нет). Список города в HTML (`div.vacancy-item`), VIP-блок с других городов не берём. Группа OK `rabotavdn` сама ссылается на этот сайт.
- **Avito** `https://www.avito.ru/gorlovka/vakansii` — **не берём HTML.** Условия использования запрещают ботов и краулеров (п. 2.4). Официальный API (`developers.avito.ru`) — для платных кабинетов работодателя, не для выгрузки чужой выдачи. Класс `PARTNER_API`. Хост в чёрном списке парсера.
- **Мой ЦЗН** `https://m-czn.ru/vacancy/g-gorlovka` — **не берём HTML.** Портал сам пишет, что вакансии ЦЗН взяты из «Работы России» (`trudvsem.ru`). Штатный путь — открытый API `opendata.trudvsem.ru` (класс `OPEN_DATA`, раздел 11.21 ядра), не вёрстка посредника. В `robots.txt` ещё `Disallow: *?*` и `*page*` — пагинацию HTML всё равно ходить нельзя.
- **Одноклассники** `https://ok.ru/rabotavdn` — **не берём HTML.** Это класс `SOCIAL`, как ВК: только официальный REST API (`apiok.ru`), с приложением и разрешением. `robots.txt` для `*` содержит `Disallow: /.*`. Группа указывает тот же контент на rabotadnr.com — его уже читаем HTML-парсером.

### Что мы делаем

- Сначала `requests` + BeautifulSoup. Playwright — только если страница без JS пустая и в конфиге `javascript: true`.
- Перед каждым URL читаем `robots.txt` хоста (шаблоны `*` и `$`, как у Bitrix `/*PAGEN`). Запрещённый путь не открываем.
- Пауза 1–3 секунды, User-Agent с адресом сайта и ссылкой на репозиторий. Потолок страниц — `max_pages`.
- Относительные ссылки → абсолютные. Ссылки на hh.ru, вход и чужой хост не ходим.
- Карточку собирает `process_post`. У вакансии `source=WEBSITE`, имя предприятия и ссылка на оригинал.

### Что мы решили не делать

- Не обходить `Disallow`, капчу и логин.
- Не подменять User-Agent под браузер «чтобы пустили».
- Не ставить Chromium в GitHub Actions, пока ни один включённый сайт не помечен `javascript: true`.
- Не читать hh.ru «вместо» карьеры предприятия.
- Не читать HTML Avito, OK.ru и посредника m-czn.ru: у первых двух правила/API закрытые, у третьего есть открытые данные «Работы России».
- Если селектор перестал находить карточки — не тихий ноль, а строка в отчёте: «сайт X: 0 элементов, вероятно, изменилась вёрстка».

## «Работа России» / Мой ЦЗН (класс `OPEN_DATA`) — Этап 18A

| Поле | Значение |
|---|---|
| Дата проверки | 2026-08-30 |
| Класс | `OPEN_DATA` (открытые данные; реконструкция + обязательная ссылка на источник) |
| Что читаем | Только `GET` JSON: `https://opendata.trudvsem.ru/api/v1/vacancies` и `…/vacancies/region/{regionCode}`. Пагинация `offset` / `limit`. Ключа API нет |
| Схема | WADL `https://opendata.trudvsem.ru/api/v1/vacancies/application.wadl` (ресурс `vacancies/region/{regionCode}`, ответ `application/json`) |
| Чем подтверждено | Портал открытых данных Роструда: https://trudvsem.ru/opendata — «информация в свободном доступе для использования без ограничений»; раздел API https://trudvsem.ru/opendata/api ; наборы https://trudvsem.ru/opendata/datasets — типовые условия использования открытых данных. Минимум типовых условий (п. 10): **указать ссылку на источник открытых данных**. Ключа и договора не требуют |
| Выключатель | `SOURCE_TRUDVSEM_ENABLED` (`true` / `false`) |
| Код | `scripts/parser_trudvsem.py`, география `scripts/sources_trudvsem.json` |

Код региона **не угадывали.** В ответе API у каждой вакансии есть объект-справочник `region`: `{ "region_code": "9300000000000", "name": "Донецкая Народная Республика" }`. Тот же код подтверждён запросом `GET …/vacancies/region/9300000000000` (2026-08-30, `meta.total` = 7951). URL, откуда взяли код: `https://opendata.trudvsem.ru/api/v1/vacancies?text=Горловка&limit=2` — поле `results.vacancies[].vacancy.region`. Отдельного ресурса «список регионов» в WADL нет: справочник — это поле `region` в JSON. Горловка в справочнике регионов как отдельный субъект не числится (это город внутри ДНР); место работы фильтруем алиасами по полю адреса. Соседний регион вместо ДНР не подставляли.

Прокси не использовали. С этой машины API отвечает по HTTPS без обхода.

2026-08-30 вечером: `GET …/vacancies/region/9300000000000?limit=1` — 200 за ~7 с; `limit=5` — 200 за ~4 с; `limit=10` и `limit=100` — Read timeout (~45–90 с). Прокси не включали. Парсер при таймауте уменьшает шаг страницы до 5 и продолжает; полный прогон с шагом 5 с этой машины был бы слишком долгим для CI — в конфиге шаг 100, GitHub Actions с другой сети может пройти его целиком.

`--dry-run --limit 3` с этой машины (шаг 5): регион 9300000000000, в API 7951; собрано 50 записей региона, 3 совпали с городом (Инженер / Слесарь / Слесарь, «ДОНБАССГАЗ», ИНН, зарплата до вычета, ссылка `trudvsem.ru`, не m-czn.ru); 47 чужих городов пропущены.

### Что мы делаем

- Только официальный GET к `opendata.trudvsem.ru`. Ответ — JSON. Пауза 1–3 с между страницами. Честный User-Agent с названием приложения и ссылкой на сайт.
- Фильтр по `region_code` из конфига, затем алиасы города. Чужой город не пишем в базу.
- На карточке и на `/about`: ссылка «Источник данных: Работа России» (`https://trudvsem.ru`) плюс ссылка на оригинал вакансии на портале (`vac_url`, хост `trudvsem.ru`).
- Зарплата этого источника — «до вычета налога» (`salaryIsGross = true`), если API не сказал иное. 13 % молча не пересчитываем.

### Что мы решили не делать

- Не читать HTML `https://m-czn.ru/` (посредник, пагинация в `robots.txt` закрыта: `*?*`, `*page*`).
- Не читать HTML `https://trudvsem.ru/` вместо JSON API.
- Не выгружать всю Россию без фильтра региона.
- Не угадывать код региона и не подставлять соседний «на глаз», если нужного нет в справочнике.
- Не обходить отказ прокси, подменой заголовков или чужим ключом. Ключа у этого API нет; если перестанет отвечать — выключатель, не обход. Таймаут большой страницы — меньший `limit`, не прокси.
