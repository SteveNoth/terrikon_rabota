# Когда уходить с бесплатного тарифа

Пороги — цифры из раздела 5.3 ядра, не ощущение. Пока цифра не достигнута, не переезжаем «на всякий случай». Пока цифра достигнута — не тянем.

Актуальный размер базы и прогноз «на сколько хватит» приходят раз в неделю в Telegram (Этап 25). Этот файл — что делать, когда прогноз уже не утешительный.

---

## 1. База > 400 МБ из 500

**Порог:** `pg_database_size` > 400 МБ (в коде `DB_MIGRATE_BYTES`). Жёсткий потолок бесплатного Supabase — 500 МБ. На 400 МБ ещё есть запас на переезд, на 500 сайт начнёт отказываться писать.

**Куда:** свой PostgreSQL. Варианты, которые подходят нашему шву (меняется только URL):

| Куда | Зачем рассматривать | Что правим |
|---|---|---|
| [Neon](https://neon.tech) | Postgres, ветки, бесплатный стартовый объём больше 500 МБ | `DATABASE_URL` + `DIRECT_URL` |
| Timeweb Cloud / Selectel / любой VPS с Postgres 16 | Дешевле на длинной дистанции, данные в своей стране | То же + бэкапы сами |
| VPS рядом с сайтом | Если одновременно уходим с Vercel | То же + Docker из Этапа 26 |

**Шаги (в этом порядке, не наоборот):**

1. Сделать проверенный бэкап: `npm run db:backup`. Дождаться зелёного workflow `hygiene-backup` (дамп восстановился на проверочной базе). Без этой галочки дальше не идём.
2. Создать пустой Postgres 16. Записать две строки: пул (если есть, как порт 6543 у Supabase) и прямое соединение (5432). Если пула нет — обе переменные могут быть одним и тем же URL.
3. В папке проекта временно подставить **новые** `DATABASE_URL` / `DIRECT_URL` в `.env.local` (старые не стирать, сохранить в парольном менеджере).
4. Накатить схему: `npx prisma migrate deploy`.
5. Залить данные: `pg_restore --no-owner --no-acl --dbname="<новый DIRECT_URL>" backups/terrikon-ГГГГ-ММ-ДД.dump`  
   Дамп — схема `public` (таблицы Prisma). Пользователи входа живут в Supabase Auth, не в этом файле — см. ниже.
6. `npx tsx scripts/recompute-counts.ts` и `npx tsx scripts/cleanup.ts --dry-run`.
7. Проверка: `SELECT COUNT(*) FROM "Vacancy";` совпадает со старой базой; `npx prisma migrate status` без pending; `/api/health` с новой базой (локально) отдаёт 200.
8. Прописать те же URL в Vercel (Production и Preview) и в GitHub Secrets (`DATABASE_URL`, `DIRECT_URL`). Новый деплой.
9. Открыть https://terrikon-rabota.vercel.app/api/health и `/gorlovka`. Список и карточки живые.
10. Старый проект Supabase не удалять две недели. Если что-то пошло не так — вернуть старые URL и задеплоить.

**Чего не трогаем:** `src/components/`, адаптеры кроме `db`. Страницы не знают, что база переехала. Prisma остаётся 6.x.

**Auth при переезде только базы:** кабинет входа остаётся на Supabase Auth, пока не меняем `AUTH_DRIVER`. Это нормально: Закон 6, два разных сервиса. Когда уедем и с Auth — отдельное решение, не этот порог.

**GeocodeCache переносим целиком.** Его не чистит гигиена специально: повторные запросы к Nominatim дороже места.

## 2. Проект Supabase «засыпает» от простоя

**Порог:** бесплатный проект без запросов к базе около семи дней уходит в паузу (в кабинете статус **Paused**). Это не размер диска, это простой.

**Что уже сделано:** GitHub Actions `keep-alive.yml` раз в 3 дня дергает `/api/health`. Пока workflow жив, пауза не должна случиться.

**Когда всё же уснул:**

1. Кабинет https://supabase.com/dashboard → проект `terrikon-rabota` → Restore / Resume.
2. Подождать 1–2 минуты. Первый запрос может идти 30–90 секунд.
3. Проверить `https://terrikon-rabota.vercel.app/api/health`.
4. Если GitHub выключил cron (60 дней без пуша в репозиторий) — любой пуш или **Actions → keep-alive → Run workflow**.

**Когда переезжать, а не будить:** если пауза повторяется, хотя keep-alive зелёный; если нужен аптайм без «первого медленного запроса»; если уже сработал порог 400 МБ. Тогда — раздел 1.

## 3. На сайте появилась коммерция

**Порог:** любая коммерция. Vercel Hobby это запрещает ([fair use](https://vercel.com/docs/limits/fair-use-guidelines)). Сюда входят платное размещение, реклама, продажа чего угодно.

**Куда:** Vercel Pro (~$20/мес за место) — код не меняем, меняется тариф в кабинете Vercel. Либо свой VPS + Docker (готовим на Этапе 26).

**Шаги для Vercel Pro:**

1. Vercel → Team `terrikon` → Billing → Pro.
2. Домен и проект `terrikon-rabota` остаются. `fra1` в `vercel.json` остаётся.
3. Коммерческие страницы можно включать только после того, как тариф уже Pro, не наоборот.

**Шаги для VPS:** Dockerfile и прогон на Этапе 26. Не начинать «свой nginx» до этого этапа: шов хостинга ещё не готов.

---

## 4. Хотим включить донаты

**Порог:** любая просьба о поддержке на сайте. У Vercel Hobby отдельная фраза: *Asking for Donations fall under commercial usage*.

**Правило проекта:** `NEXT_PUBLIC_DONATIONS_ENABLED=false`, пока сидим на Hobby. Кнопки, страницы и упоминаний нет в HTML, не «скрыто CSS».

**Куда (сверить условия перед решением — они меняются):**

| Куда | Донаты | Сложность |
|---|---|---|
| Vercel Pro | Разрешены | Нулевая |
| Свой VPS | Разрешены | Средняя, Этап 26 |
| Netlify, бесплатный тариф | Коммерция разрешена | Перепроверить middleware и кэш Next |
| Cloudflare Pages/Workers, бесплатный | Коммерция да, карты на бесплатных сервисах — нет | Нужен адаптер Next; наши донаты — внешние ссылки, карт мы не принимаем |

**Нельзя:** оставить сайт на Hobby, а страницу доната вынести на другой хостинг и поставить ссылку. Просьба всё равно исходит от развёртывания на Vercel.

**Порядок:** сначала переезд хостинга → потом `NEXT_PUBLIC_DONATIONS_ENABLED=true` → потом страница поддержки. Не наоборот.

## 5. Трафик > 100 ГБ/мес

**Порог:** 100 ГБ исходящего трафика в месяц (лимит, вокруг которого живём).

**Где смотреть:** Vercel → проект `terrikon-rabota` → Analytics / Usage. Не путать с трафиком GitHub Actions.

**Куда:** CDN (Cloudflare перед сайтом) + при устойчивом росте — свой хостинг.

**Шаги:**

1. Включить Ultra Lite по умолчанию, если ещё не (`NEXT_PUBLIC_DEFAULT_QUALITY_MODE=lite` уже стоит; для совсем тонкого — `ultra`).
2. Проверить, что карта не в первой загрузке (Этап 13) и `npm run check:budget` зелёный.
3. Поставить Cloudflare Proxy на домен, когда свой домен появится. Пока домен `*.vercel.app` — Cloudflare как оранжевое облако не повесить; тогда либо свой домен, либо переезд с Hobby.
4. Картинки по-прежнему не храним (Закон 10).

## 6. GitHub Actions > 1800 из 2000 минут (приватный репозиторий)

**Порог:** 1800 минут из 2000 в месяц. Публичный репозиторий минуты не лимитирует.

**Где смотреть:** GitHub → Settings аккаунта **SteveNoth** (не репозитория) → Billing → Actions. Репозиторий сейчас публичный; если сделаем private — этот порог оживает.

**Что сделать, в порядке дешевизны:**

1. Оставить репозиторий публичным. Код без секретов; секреты только в GitHub Secrets.
2. Если всё же private: перенести парсеры и гигиену на свой сервер (cron / systemd). Workflows тогда только ручная кнопка.
3. Не отключать `hygiene-backup` и `keep-alive`: минуты дешёвые, молчание дорогое.

Оценка минут гигиены: счётчики и отчёт размера — короткий curl раз в час / раз в неделю. Очистка — `npm ci` раз в сутки, порядка нескольких минут. Бэкап — раз в неделю, `pg_dump` + `pg_restore`. Парсеры едят больше, чем гигиена.

## 7. Парсеры не успевают: > 8 минут на один запуск

**Порог:** один workflow парсера (ВК / Telegram / сайты / ЦЗН) стабильно дольше 8 минут. GitHub убивает job по `timeout-minutes`; даже если не убивает, мы вылезаем за «короткий бесплатный cron».

**Где смотреть:** Actions → конкретный parser-* → длительность. Не среднее «когда API тупил», а несколько запусков подряд.

**Куда:** свой сервер и очередь задач. Парсеры уже не живут на Vercel (10 секунд функции). Меняется только место запуска Python, не `process_post`.

**Шаги:**

1. Сначала урезать работу: `--limit` не для продакшена; проверить паузы `VK_REQUEST_GAP_SEC` / `TG_CHANNEL_GAP_SEC` — не раздуты ли.
2. OCR и Playwright оставляем только там, где без них пусто (Этапы 14B, 18).
3. Когда стабильно > 8 минут — перенести `scripts/parser_*.py` на VPS, cron как в yml. `CRON_SECRET` + `SITE_URL` те же: дверь `/api/parser/upload` не меняется.
4. Очередь задач (Redis/Bull) — после переезда на платный стек, не до него. Адаптер кэша уже есть задел.

## 8. Поиск тормозит: > 500 мс на запрос

**Порог:** сам SQL списка/поиска в том же регионе, что база (`fra1` + Frankfurt), p95 > 500 мс. Замер с домашнего ПК до Франкфурта в эти 500 мс не входит: это дорога, не индекс.

**Как замерить:** `node scripts/bench-vacancies.mjs` (EXPLAIN ANALYZE). В плане должен быть `Vacancy_citySlug_isActive_workFormat_publishedAt_idx`.

**Куда:** Meilisearch / Typesense через уже существующий `src/lib/adapters/search.ts` (`SEARCH_DRIVER`). Страницы по-прежнему зовут адаптер, не движок.

**Шаги:**

1. Убедиться, что тормозит SQL, а не RTT. Если RTT — раздел не про поиск.
2. Проверить, что запрос не «достать все и фильтровать в JS» (Закон выдачи).
3. Поднять Meilisearch (свой VPS или облако), прописать `SEARCH_DRIVER=meilisearch` и URL. Реализацию драйвера пишем в момент переезда, не заранее.
4. Индексировать только поля карточки, не `rawText`.

Пока строк тысячи, Postgres хватает. Этот порог — про рост после нескольких городов, не про Горловку 2026.

---

## Что не является порогом

- «База выросла на 5 МБ за месяц» — смотрим прогноз в Telegram, не переезжаем.
- Одна неудачная выгрузка бэкапа — чиним workflow, не меняем стек.
- Vercel предупредил про fair use без коммерции на сайте — сначала выключаем то, что похоже на коммерцию (донаты уже за выключателем).

---

## Бэкап, без которого переезд не начинаем

- Команда выгрузки: `npm run db:backup` → файл в `backups/` (папка в gitignore).
- Расписание: `.github/workflows/hygiene-backup.yml`, воскресенье 04:10 UTC.
- Артефакт Actions хранит **зашифрованный** дамп 30 дней. Пароль — `BACKUP_PASSPHRASE` (если пуст, берётся `CRON_SECRET`).
- Обязательная проверка: тот же job восстанавливает дамп на одноразовый Postgres 16 и смотрит, что живы `Vacancy`, `GeocodeCache`, `_prisma_migrations`.
- Бэкап, который не проходил этот restore, **не считается бэкапом**.

Подробные команды для этой машины — `docs/SETUP-LOG.md`, Этап 25.
